# ARCHITECTURE_CSS.md

CSS & layout reference for this repo — the "how is [style/](style/) built and why" chapter split out of [ARCHITECTURE.md](ARCHITECTURE.md) (see that file for the JS/data architecture). **Keep this file in sync**: whenever you change the styles it describes, update the matching section here in the same edit.

**File split** (no preprocessor, plain CSS in all five): `style/base.css` (fonts, KaTeX sizing, theme/colour variables, `body`, global error message), `style/sheet.css` (corner chrome + sidebar, PDF panels, exercise cards, all answer-type styles, solution panel, widgets, misc forms/tables), `style/landing.css` (`.landing-*`, index.html only), `style/exam.css` (exam mode + open-exercise indicators), `style/responsive.css` (breakpoints). **Load order is the cascade and must be preserved**: `base` → `sheet` → `landing` → `exam` → `responsive` (`responsive.css` last, so its overrides win). `template.html` `<link>`s all five; `index.html` only needs `base.css` + `landing.css`. The page is one centred column; `body` is `text-align: center` and most block widths are fixed at **650px** (`.exercise-container`). Section banners use `/* ===== NAZWA ===== */` comment headers, in Polish — follow that convention.

**Theme / colour variables (dark mode).** All colours go through CSS custom properties defined in `:root` near the top of `style/base.css` (semantic tokens: `--bg`, `--bg-muted`, the `--text*` tiers, `--border*`, `--accent-*`, `--correct`/`--incorrect`, `--score-*`, `--overlay-bg`, `--canvas-bg`, …). `:root` holds the **light** values (unchanged from the pre-variable design). The **dark** palette is written in **two twin blocks that must be kept identical**: `@media (prefers-color-scheme: dark) :root:not(.theme-light)` (system/auto) and `html.theme-dark` (manual override, wins over the system). Manual light is `html.theme-light` (it just suppresses the system rule, leaving `:root`). `--canvas-bg` **does** darken with the theme (changed 2026-08-06, `#fff` → `#1c1c1c`; since 2026-08-09 it is `#141414`, i.e. **identical to `--bg`** — the widget canvas must be indistinguishable from the page, it is exercise content, not a card), together with the whole **widget palette** — a block of `--wg-*` tokens (`--wg-osie`, `--wg-siatka`, `--wg-tekst`, `--wg-linia`/`-slaba`/`-mocna`, `--wg-punkt`, `--wg-zolty`, `--wg-slupek`, `--wg-etykieta-info` and the translucent `--wg-obszar-*`/`--wg-slupek-ok` fills). Canvas ignores CSS, so these are read back in JS (`WG_KOLORY`/`wgOdswiezKolory`, see ARCHITECTURE.md "Rendering model") — which is exactly why a new widget colour must become a token here rather than a literal in `widgets/*.js`. The CKE **images and Manim videos** (opaque white background at the source) get a dark-mode-only `filter: var(--filtr-grafik-zadan)` instead of a colour token — `none` in `:root`, `invert(92%)` in both dark blocks (92% chosen so inverted white lands on the same grey as `--bg`; deliberately no `hue-rotate` compensation, so on-image colours come out swapped) — applied in `style/sheet.css` to `.question img` and to `img`/`video` inside `.solution-step-by-step-container`. When adding new colours, use a token (add one if needed) rather than a raw hex, and set both a light (`:root`) and a dark (both dark blocks) value.

**Shape tokens (added 2026-07-27, "spójność UI" pass).** Alongside the colours, `base.css` defines the shape of every control, so a restyle happens in one place instead of 25: `--radius-kontrolka` (6px — everything clickable in the content: answer buttons, inputs, footer buttons, PDF panels, landing cards/CTA) and `--radius-pigulka` (6px — chrome: logo, corner pills, mode switch, sidebar rows). They are deliberately **equal**; split them only if the two families must really differ. `--border-kontrolka` (1px) is the default control border — a 2px border now only survives where it **carries meaning** (`.wg-a`/`.wg-b` encode a widget value's colour). `--shadow-panel` is the shared floating-panel shadow (PDF panels, toast — **not** the sidebar, which Henrich had de-shadowed on 2026-07-27), intentionally small and soft; `--shadow-modal` (added 2026-08-09, "spójność UI etap 2") is the deliberately stronger sibling for full-page modals — today only the exam-summary window `#egzamin-podsumowanie .egzamin-okno`, which also picked up `--radius-kontrolka` in the same pass (it was the last sharp-cornered "card"). Both shadow tokens have a **different dark value** (same geometry, higher opacity, because a shadow barely reads on a dark background), so they live in both dark blocks too.

**Hover rule (Henrich's decision, 2026-08-09, written down at `#naroznik-prawy button:hover` in sheet.css):** page **chrome** (corner pills, `#sidebar-toggle`, sidebar rows, mode switch, panel ✕s, landing theme toggle) hovers by **background highlight** (`--bg-muted`/`--bg-hover`), border untouched; **content controls** (ABCD/PF/self-score answers, „sprawdź" buttons, footer buttons, report-form pills) hover by **border darkening** (`--border-strong`) — their background and inset box-shadow already carry the correct/incorrect/`.selected` states, so a background hover would collide with them. The answer buttons gained a `:hover` in the same pass (they had none), guarded with `:not(.correct):not(.incorrect):not(.selected)` so graded/selected buttons don't react.

**Control size scale on the exercise card** (2026-08-09, documented at the „PRZYCISKI ODPOWIEDZI" banner in sheet.css): three tiers — **duża** (ABCD/multiselect answers: 18px, padding 10px 12px), **kontrolka** (fillIn/final-answer inputs and self-score buttons: 17px, padding 8px 11px), **tekstowa** (the `.open-answer` textarea: 16px, padding 10px 12px); the two „Sprawdź" buttons next to fields are a shared 15px / 8px 18px. P/F stays 44px/16px on purpose (its size is its meaning). The 2px `border-bottom` separators between solution sub-blocks and `#wskazniki-ukryj`'s 2px border went down to 1px in the same pass — width there carried no meaning (unlike `.wg-a`/`.wg-b`). Light `--text-faint` darkened `#858585` → `#767676` for WCAG AA (4.5:1) at the 13px footers/disclaimer/`#total-score`; the dark value already passed. `--segment-bg`/`--segment-text` are the mode switch's active half (see "Górne narożniki"). Before hard-coding a radius, border width or shadow, check whether one of these already says it. The toggle is `#theme-toggle` in the sidebar (cycles auto → jasny → ciemny — the one setting that cycles *rightward*, see "Panel boczny"), persisted in localStorage under the **global** key `matematykazen-motyw` (no sheet id — shared across sheets); a tiny inline `<head>` script in template.html **and** index.html applies the saved class to `<html>` before first paint to avoid a theme flash.

## Górne narożniki (`#naroznik-lewy` / `#naroznik-prawy`)

**There is no top bar any more** (`#top-bar`, `#bar-container`, `#bar-left/center/right` were deleted 2026-07-26). Two independent `position: fixed` clusters float in the top corners with no shared background, no full-width row and no shared width — so, unlike the bar, they cannot push the page sideways. Do **not** reintroduce a full-width bar, and do **not** go back to the pre-bar pattern either (hard-coded negative offsets like `right: -330px`, which overlapped whenever the title, score width, or window size changed).

- Both clusters: `position: fixed; top: 16px; display: flex; align-items: center; gap: 8px; z-index: 10` — the same layer the bar had, i.e. above the PDF panels (9) and below the sidebar (12). `#naroznik-lewy { left: 20px }`, `#naroznik-prawy { right: 20px }`. Under 720px the offsets tighten to `top: 10px` / `8px`.
  - **One exception (2026-08-14): `body.sidebar-otwarty #naroznik-lewy { z-index: 13 }`**, i.e. above the scrim (11) *and* the panel (12) while the sidebar is open. The chevron is the only way to close the panel on a phone, but the full-screen scrim used to lie on top of it: it looked greyed out (so, disabled), took no hover, and the click landed on the scrim. The panel still closed — a click on the scrim is its second close path (`app/bootstrap.js`) — which is why the defect stayed invisible for so long. The corner ends above the panel's top edge (56px, 48px under 720px), so the higher layer covers nothing. Two rejected alternatives: starting the scrim at 56px instead of `inset: 0` leaves an undimmed strip of exercise text above the panel, and dropping `#logo`'s background while open lets that text show through the wordmark (the logo keeps its rectangle, so both it and the chevron read as lifted).
- `#naroznik-lewy` → `#logo` (an `<a>` to index.html) + `#sidebar-toggle` (the chevron that opens the panel). `#logo` has a **fixed `min-width: 200px`** background rectangle, no border: PDF panels pass *underneath* it (z-index 9 < 10), so its backdrop must be predictable rather than growing with the version number. Reset to `min-width: 0` under 720px, where the rectangle is pointless (phones open PDFs in a new tab, not as a draggable window).
- `#naroznik-prawy` → in DOM order `#egzamin-timer`, `#total-score`, `#egzamin-koniec-bar`. Timer and "zakończ" are exam-only (hidden outside `body.tryb-egzaminu`); `#total-score` is hidden *inside* exam mode by `exam.css` with `!important` — deliberately, a visible running total would leak which answers were right. `#egzamin-koniec-bar` holds `<span class="tylko-szeroko"> egzamin</span>`, hidden under 560px so the label shortens to "zakończ" and the whole cluster still fits beside the logo at 360px.
- **Pills.** One shared rule in `sheet.css` gives `#total-score`, `#egzamin-timer` and `#naroznik-prawy button` their box: `padding: 6px 12px`, `border: 1px solid var(--border)`, `border-radius: var(--radius-pigulka)`, `background-color: var(--bg)`, `font-size: 13px`. The **background is load-bearing, not decoration** — without the bar these elements scroll over the exercise text and would otherwise blend into it. `exam.css` only adds visibility and what differs (tabular-nums on the clock, muted colour). Pill hover is a background highlight (`--bg-muted`), not a border change — see the hover rule under "Shape tokens" above. `--radius-pigulka` (6px, `base.css`) is the single knob for chrome rounding, and since 2026-07-27 the content controls use the equal `--radius-kontrolka` — there is no longer a second, hard-coded 3px scale.
- `#tryb-przelacznik` — the ćwiczenia/egzamin segmented control, second child of `#exercises-wrapper` right after the `<h1>`. Successor to the old passive `#exercises-mode-subtitle` label. Deliberately **not** fixed (it scrolls with the content; the clock in the right cluster is what stays visible during an exam). `display: none` until `body.arkusz-wczytany`, like `#egzamin-start-stopka`, so it never offers to start an exam on a bad-`?arkusz=` error page. The active half was a **full inversion** (`background: var(--text)`) until 2026-07-27; Henrich found it too heavy for a small control (a black block in light mode, near-white in dark), so it is now a soft fill: `background: var(--segment-bg)` + `color: var(--segment-text)` + `font-weight: 600` — lighter than black in the light theme, darker than white in the dark one, with weight (not inverted colour) carrying part of the state. Keep both signals: with such a subtle background, dropping the weight makes the selection hard to spot. Only `updateModeSwitch()` (`app/exam.js`) writes its `.aktywny`/`aria-pressed` state; the click handlers just call `startExamPrompt()`/`finishExamPrompt()`, so cancelling the `confirm()` cannot leave it in a wrong state.

## Panel boczny (`#sidebar`)

Replaces the `⋯` dropdown (`#menu-button` + `#bar-menu`, both deleted from DOM and CSS 2026-07-27). A slide-out **overlay** on the left: the sheet never moves (no `transform` on the content, no narrowed column), and only `transform` is animated — `left`/`width` would force layout every frame.

- `#sidebar` — `position: fixed; top: 56px; bottom: 0; left: 0; width: 260px; z-index: 12` (must be above the PDF panels), `overflow-y: auto`, **no shadow** (removed 2026-07-27 at Henrich's request: the panel is pinned to the screen edge and already has its own `#sidebar-linia` rule, so a shadow doubled that boundary and lifted the panel off a page it visually belongs to; the floating PDF panels and the toast keep theirs, having no rule of their own). It starts *below* the corners so the logo and chevron stay visible and clickable above it — the same chevron closes it. Under 720px `top: 48px`; under 560px `width: 100%`.
- **The vertical rule beside the panel is a separate element, `#sidebar-linia`** (added 2026-07-27), not the panel's `border-right`. Henrich wanted it pushed right of the panel and ending above the bottom of the screen — a border can do neither, and it would scroll with the panel's content (`overflow-y: auto`). A `#sidebar::after` with `position: fixed` does not work either: `#sidebar` has a `transform`, so it becomes the containing block for `fixed`, and `overflow` clips the pseudo-element. So: `position: fixed; top: 72px; bottom: 40px; left: 276px` (panel width + 16px), 1px of `--border-strong`, `z-index: 12`, `pointer-events: none`, `opacity` 0→1 tied to `body.sidebar-otwarty` on the same 180ms curve as the slide. Under 720px `top: 64px` (the panel starts higher); under 560px `display: none` (a full-width panel has nothing to separate). No JS touches it.
- `#sidebar-toggle` is nudged `margin-left: -4px; margin-top: -2px` on desktop so the chevron reads as part of the left corner (zeroed under 720px, where the corner is already tight). **It must be `margin`, not `transform`** — `body.sidebar-otwarty #sidebar-toggle` sets `transform: rotate(180deg)`, which would override any `translate` and make the chevron jump the moment the panel opens.
- **Open/close.** `body.sidebar-otwarty` drives everything. `transform: translateX(-100%) → 0` over **180ms `cubic-bezier(.2,.7,.3,1)`**; `#sidebar-toggle` rotates 180° on the same curve and duration. Closed state also needs `visibility: hidden` so Tab skips the panel's buttons — `translateX` alone does not. **Gotcha:** it is written as `visibility 0s linear 180ms` in the base rule and `visibility 0s linear 0s` in the open rule (delay, not duration). A plain `visibility 180ms` leaves the computed value `hidden` in the very frame the class lands, and `otworzSidebar()` then has nothing focusable — even from inside `requestAnimationFrame`.
- **Threshold 1300px** ("the panel covers the content"). Card = 650px + 2×50px padding = 750px; with a 260px panel + 16px gap the left margin suffices from `(750/2 + 276) × 2 ≈ 1300px`. The threshold governs three behaviours at once, deliberately tied to width rather than `czyTelefon()` (a narrow laptop hides the exercise exactly like a phone): the `#sidebar-przyciemnienie` scrim (`rgba(0,0,0,.25)`, `opacity` 0→1 in 180ms), closing on a click in the sheet, and closing after an **action** is clicked. The first two are pure CSS — the scrim's `pointer-events` is `none` above the threshold and `auto` below (`responsive.css`), so no JS test is needed; only the action case reads `sidebarNaklada()` in `app/bootstrap.js`, which must stay in sync with the media query. Clicking a **setting** never closes the panel at any width (cycles get clicked several times in a row).
- **Scroll lock under the open panel** (2026-08-09). Below the 1300px overlap threshold, opening `#sidebar` also puts `body.blokada-scrolla` (`position: fixed; overflow: hidden`) on the body, so a vertical swipe next to the panel no longer scrolls the sheet behind it. `position: fixed` rather than `overflow: hidden` alone because iOS Safari ignores the latter; the resulting jump-to-top is paid for in JS (`zablokujScrollTla`/`odblokujScrollTla` in `app/bootstrap.js` stash `scrollY` into a negative inline `top` and restore it with `scrollTo`). `#sidebar` is itself `position: fixed` with `overflow-y: auto`, so its own scrolling is unaffected. A `resize` handler drops the lock if the window grows past the threshold with the panel open.
- **Two row types.** `.sidebar-akcja` — a verb, `display: flex`, 40px tall, `--text`, hover `--bg-muted`. `.sidebar-ustawienie` — a noun plus current value, `display: grid; grid-template-columns: 20px 1fr auto auto` (icon | label | value | dots) — a grid, *not* flex with `margin-left: auto`, so values line up vertically between rows. Label `--text-muted`, value `--text` at `font-weight: 400`, **no accent colour** (`--accent-blue-strong` already means "your choice in an exercise"; green/red mean correctness). `.sidebar-sub` is the same control indented 26px at 12px font for the two exam sub-options. A thin `.sidebar-kreska` (1px, `--separator`) splits actions from settings — no section heading, no empty gap. **Both of those values changed on 2026-08-09 and the reasons are load-bearing:** the label was `--text-faint-2` (#909090 / #8c8c8c), which put the *normal* state on the same side of the scale as a genuinely `disabled` row — and since `disabled` is now used outside exam mode too (see `#sidebar button:disabled` below), "greyed" has to mean "off", not "default". The value was `font-weight: 600`; Lora is a high-contrast serif and its 600 face at 12px clots the serifs into a blur (worst as light text on dark — Henrich reported it as bleeding/bloom). Diagnosed by comparing 600/400 at ×5 zoom on a single row: the cause was the weight, not the segment background. Hierarchy between label and value is now carried by colour and the dots, not by weight; the inactive `.kropka` moved `--border-muted` → `--border-strong` for the same contrast reason.
- **State lives in attributes.** `data-stany` is the comma-separated list of value labels left→right (convention: leftmost = off, rightmost = "wszystko", so the dots read as a scale: `●○○` off, `○○●` full) and `data-stan` is the current one — the **single source of truth** for cycle position. `data-kierunek` defaults to leftward ("each click takes one step off", because the default value sits at the right end); only `#theme-toggle` is `"prawo"`, since a theme is not a more/less scale. `ustawWartosc()`/`nastepnyStan()` in `app/state.js` read those attributes for both the cycle and the `.kropki` dots (generated, never hand-written in HTML), so the two cannot drift apart. Every toggle's JS maps that label to its own localStorage representation. (Until 2026-08-10 there was a third reader, a `.wartosc-podglad` hover preview showing "auto → jasny" — removed because it hid the current value on hover instead of clarifying it; archived in `issues/archiwum-hover-podglad.md`.)
- **Never write `textContent` on a sidebar button** — it would wipe the SVG icon, label, value and dots in one go. Use `ustawEtykiete()` (actions whose verb changes: `#toggle-tablica`, `#toggle-zasady`, `#show-all-solutions`) or `ustawWartosc()` (settings), both in `app/state.js`. (Writing `textContent` on a **dedicated child span** you own — like `#sprawdz-wszystkie-status-sidebar` below — is fine; the rule is about the button's own root text node.)
- **"sprawdzono ✓" confirmation (added 2026-07-27, issues/sprawdz-wszystkie-pola-i-komunikat.md, now done/04-biezace.md).** `#sprawdz-wszystkie` gets one extra child, `.sprawdz-status-sidebar` (`margin-left: auto` — free, since `.sidebar-akcja` is already `display: flex`): 260px has no room for a sentence next to the label, so the visible content is just a "✓" glyph, coloured via token (`--correct` normally, `--text-faint` + `.przygaszony` when nothing was selected to check — otherwise "sprawdzono" would lie). The real sentence for screen readers goes into `aria-label` (JS, `pokazStatusSprawdzania()` in `app/bootstrap.js`), not the visible text — the glyph alone would read as "check mark" to a screen reader, which says nothing. `role="status" aria-live="polite"` sit in the HTML permanently (not toggled by JS) so a content change is always picked up. Fades via `opacity`/`.widoczny` (400ms), auto-hides after ~2.5s (JS `setTimeout`, reset by the next click), and is folded into the shared `prefers-reduced-motion: reduce` block above (`transition-duration: 0.01ms`).
- **Disabled rows.** `#sidebar button:disabled` → `opacity: 0.4; cursor: not-allowed` (moved here from `style/exam.css` on 2026-08-09). Two independent reasons set the attribute, both resolved in `odswiezBlokadyMenu()` (`app/exam.js`, see ARCHITECTURE.md "Exam mode"): a running exam, and — for `#sprawdz-wszystkie` — immediate-correctness mode. The row is never *hidden*: `#sprawdz-wszystkie` used to `display: none` under `body.reczne-sprawdzanie` and the whole panel jumped every time "Poprawność" was toggled.
- **Swipe-to-close (phone only, `app/bootstrap.js`).** Touch listeners live on `#sidebar` alone, are all `passive: true` and never call `preventDefault()` — the gesture only *observes* the touch, so the panel's own vertical scrolling and any dragging over exercise content are untouched. Thresholds: ≥60px horizontally, ≤45px vertically, |dx| > 1.5·|dy|, ≤700ms, ≥0.25px/ms; a touch starting within 24px of the right viewport edge is ignored (that is the browser's own forward-navigation gesture, which also travels leftwards) and a second finger cancels the gesture.
- **Text budget.** 260px minus padding, icon, gaps, value and dots leaves only **~85–100px for the label** (an earlier estimate of "~200px" ignored the value and dot columns). That is why `Wskaźniki` and `Poprawność` are shortened to one word with the full phrasing in `title`; `.wartosc` is 12px for the same reason. Check `etykieta.scrollWidth > clientWidth` across *all* states before adding a row.
- **Icons.** Inline `<svg class="sidebar-ikona" viewBox="0 0 24 24" aria-hidden="true">` in template.html — zero files, works offline, inherits the theme colour. The shared attributes (`20×20`, `fill: none`, `stroke: currentColor`, `stroke-width: 1.5`, round caps/joins) live in the CSS rule, not on each element; individual shapes opt into `fill="currentColor" stroke="none"` where they need a solid. Sub-option icons get `opacity: .7`.
- **Keyboard / SR.** `#sidebar-toggle` is `<button aria-expanded aria-controls="sidebar" aria-label>`; JS flips `aria-expanded` and swaps the label between "Otwórz menu"/"Zamknij menu". Esc closes **and returns focus to the chevron**; opening moves focus to the first visible enabled row (inside `requestAnimationFrame`, see the visibility gotcha above). Deliberately **no focus trap** — the panel is not a modal, you can Tab out into the sheet. The header is an `<h2 id="sidebar-tytul">` (filled by `applySheetMeta()` from the same `meta.sheetTitle` as `#sheet-title-heading`), not a `<div>`, and not a button.
- `@media (prefers-reduced-motion: reduce)` drops every duration above to `0.01ms` **and zeroes `transition-delay`** — otherwise the closed panel would linger `visible` for 180ms after sliding out.

**Keep these IDs stable when restyling** — they are all looked up by `app/*.js` (`getElementById`), so deleting or renaming one silently breaks a feature even though the markup "looks" inert:
  - **Corner chrome:** `#logo`, `#wersja`, `#total-score`, `#sidebar-toggle`. Exam-only (hidden outside `body.tryb-egzaminu`, but always in the DOM): `#egzamin-timer`, `#egzamin-koniec-bar`. Mode switch: `#tryb-przelacznik`, `#tryb-cwiczenia`, `#tryb-egzamin`.
  - **`#sidebar` items** (all `getElementById`-wired): actions `#toggle-tablica`, `#toggle-zasady`, `#egzamin-start`, `#egzamin-koniec-menu`, `#sprawdz-wszystkie`, `#show-all-solutions`, `#reset-scores`; settings `#zegar-toggle`, `#wskazniki-tryb-toggle`, `#theme-toggle`, `#score-switch-button`, `#natychmiastowa-toggle`, `#zglos-blad-toggle`. Plus `#sidebar-tytul`, `#sidebar-przyciemnienie` and `#sprawdz-wszystkie-status-sidebar` (the "sprawdzono ✓" confirmation span inside `#sprawdz-wszystkie` — see "Exercise cards & solution panel" below for its sheet-footer twin).
  - **PDF panels:** `#tablica-wzorow-panel`, `#tablica-wzorow`, `#tablica-close`, `#zasady-oceniania-panel`, `#zasady-oceniania`, `#zasady-close`.
- `#tablica-wzorow-panel` — the floating formula-sheet panel: `position: fixed`, top-right, `display: none` until the JS toggles it to `block`. `z-index: 9` (just under the bar). It's a container around the PDF `<object id="tablica-wzorow">` (which fills it at `width/height: 100%`, borderless) plus `#tablica-close` — the ✕ close button absolutely positioned in the panel's top-right corner. The panel owns the border/shadow/size; the `<object>` is what `openFormulasAtPage` swaps out, so keeping the chrome on the wrapper means a page change never loses the border or the close button. `#zasady-oceniania-panel` shares all these rules (selector lists) and only overrides `right: auto; left: 30px`. Both carry class `.pdf-panel` (`box-sizing: border-box; padding-top: 40px` making room for the drag strip): `.panel-uchwyt` (40px top strip, `cursor: move`, `touch-action: none`) and `.panel-rozmiar` (22px bottom-right grip, `cursor: nwse-resize`) are the drag/resize handles wired by `makePanelDraggable`.
- **PDF panel chrome follows the sidebar** (Henrich's decision, 2026-07-27): same `--border-strong` border, `--radius-kontrolka`, `--shadow-panel`; the drag strip sits on `--bg` with a 1px `--separator` hairline and the sidebar heading's typography (14px/600) instead of the old grey `--bg-muted` slab, which was what stood out in dark mode; the ✕ follows the `.zglos-blad-x` pattern (32px, 1px border, no shadow) instead of the old deliberately-loud 40px bold button with a shadow — it no longer sits on a grey slab, so it does not need to shout. **The PDF page itself stays white**; tinting the `<object>` remains unaddressed (unlike `.question img`/step videos, which do get a dark-mode filter — see the theme-variables note above). The strip's height is read from the DOM (`uchwyt.offsetHeight || 46` in `app/panels.js`), so changing it in CSS is safe.

## Exercise cards & solution panel

- `.sheet-title-heading` — the sheet's `<h1>`, first child of `#exercises-wrapper` (so it renders above every exercise, filled in by `applySheetMeta()`): centred, `font-size: 24px`, `font-weight: 600`, and since 2026-07-27 `max-width: 32%; margin: 0 auto 20px` — full width dragged the CKE title into one long line across the screen, 32% (~460px at 1440px) wraps it onto two or three centred lines. The cap is lifted under 720px (`max-width: none`), where 32% of 390px would leave two words per line. `:empty { display: none }` keeps it from reserving space before the meta fetch resolves.
- `.exercise-container` — the per-exercise row (650px wide, centred with `margin: auto`, `padding: 50px`, left-aligned text, `font-size: 18px`), cloned from the hidden `#exercise-template`. ## Responsive breakpoints

The layout is still desktop-first (650px column), but `style/responsive.css` (the whole file, one `/* ===== RESPONSYWNOŚĆ ===== */` section, loaded last so it wins the cascade) adapts it downwards; **no horizontal scroll from 360px up** (verified by a Playwright sweep at 360/400/720/800/900/1000/1024/1100/1280). The breakpoints:

- `max-width: 1299px` — the sidebar scrim turns on (`opacity: 1; pointer-events: auto`). See "Panel boczny" above for why 1300px and what else the threshold controls; `sidebarNaklada()` in `app/bootstrap.js` mirrors this query and must be changed with it.
- `max-width: 1024px` — the `.exercise-score` badge moves from `right: -120px` (outside the card; fits only when the window is ≥ ~1010px) into the card's top-right corner.
- `max-width: 720px` — the exercise's light-button row wraps two-per-line (`flex-wrap: wrap`, `flex: 1 1 40%`); corner offsets tighten (`top: 10px`, `left/right: 8px`), pill padding shrinks, `#logo` drops its 200px `min-width`, `#sidebar` starts at `top: 48px` (and `#sidebar-linia` at `top: 64px`), `#sidebar-toggle` loses its desktop `margin` nudge, `.sheet-title-heading` loses its 32% cap; `.exercise-container` becomes fluid (`width: auto; max-width: 650px`, smaller padding); step videos scale to container width (`aspect-ratio: 420/180` keeps the shape); answer buttons go to `min-width: 38%` (≈2 per row) **except** `.pf-row button`, which must stay 44px (the P/F buttons share `.button-container` with the ABCD ones, so they'd otherwise inherit the widening); PDF panels span 94% of the screen; `.sprawdz-status-stopka` (the "sprawdzono ✓" message beside the footer's "sprawdź wszystkie" button, see "Exercise cards & solution panel") repositions from beside to below-centred the button — still `position: absolute` (never back into flow, or an empty/invisible message would still reserve height and make the button look permanently oversized) — because the centred button's message otherwise routinely overflows the viewport here.
- `max-width: 560px` — `#sidebar` goes full-width and `#sidebar-linia` is hidden; `#logo` to 14px; `#egzamin-koniec-bar` drops its `.tylko-szeroko` span so the label is just "zakończ" (without that the right cluster wraps beside the logo at 360px); `#naroznik-prawy` may still `flex-wrap` onto a second row as a safety net, and `body.tryb-egzaminu #exercises-wrapper` then gets `padding-top: 92px` so the title clears it.
- Still `max-width: 560px` (same block) — the floating "oceń się" indicator dots (`.wskaznik-otwarte`) and their "Ukryj wskaźniki" button (`#wskazniki-ukryj`) are hidden outright: their fixed `right: 70/96px` positions assume desktop width and can crowd narrow-phone content; every open exercise's self-score row still works normally without them.

Wide KaTeX display blocks get their own `overflow-x: auto` (on `.katex-display`, in the KaTeX rule near the top of `style/base.css`) instead of stretching the page.

## Known layout gotchas

- Spacing for the floating corner clusters is `padding-top: 66px` on `#exercises-wrapper` (`base.css`) — a pill ends around 45px (`top: 16px` + ~29px tall), the rest is breathing room. If you change the pills' `top` or height, adjust that padding **and** the `responsive.css` overrides (56px @720, 92px @560 in exam mode).
- **The 12px horizontal scroll at 360px was never the top bar.** Sonnet's TODO entry blamed `#top-bar` (373px), but after deleting the bar the page still measured 372px: the real source was `table.data-table` in zad. 33. It now gets its own `display: block; width: fit-content; overflow-x: auto` (the same treatment `.katex-display` gets in `base.css`). Re-measure `documentElement.scrollWidth` vs `clientWidth`, don't assume the widest *chrome* element is the culprit.
