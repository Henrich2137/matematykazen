# ARCHITECTURE.md

Detailed architecture, data-schema and CSS/layout reference for this repo. Read this **before** touching the rendering logic in [app/](app/) / [widgets/](widgets/), the data schema in a sheet's `exercises.json` (under [matura/](matura/)), or anything in [style/](style/).

> **Script layout.** `template.html` (root) is the **single renderer for every sheet** — the per-sheet `matura/<id>/index.html` copies are gone. At the bottom it loads a run of external classic scripts in order: `widgets/_helpers.js` (shared `wg*` helpers), the nine `widgets/*.js` widget files, `widgets/_registry.js` (the `WIDZETY` registry) **then** the ten [app/](app/) files in a fixed order (`state.js` → `theme.js` → `exam.js` → `indicators.js` → `panels.js` → `answers.js` → `steps.js` → `report.js` → `render.js` → `bootstrap.js`; CLAUDE.md lists what each one owns). Order matters — `loadExercises` in [app/render.js](app/render.js) reads the `WIDZETY` const declared in `widgets/_registry.js`, which in turn reads the `widget*` functions declared in the individual widget files, and classic scripts share one global scope, so each declaring file must run before whatever reads it.

> **Which sheet is rendered** is chosen by the URL query param `?arkusz=<id>`, where `<id>` is a folder name under `matura/` (e.g. `template.html?arkusz=2026-maj`). [app/state.js](app/state.js) reads it into `SHEET_ID` (`new URLSearchParams(location.search).get("arkusz")` — **no default fallback**: a missing, empty, or unknown `?arkusz=` shows a "Błędny link" message with a link back to `index.html`, see "Data loading") and uses that one id for everything sheet-specific: the `fetch` path (`matura/<id>/exercises.json`), the localStorage key suffixes, and `mediaPath()` (see "Asset folder convention"). The landing page ([index.html](index.html)) links to each sheet as `template.html?arkusz=<id>`. There is no backend/redirect — it is a pure static page.

> **Keep this file in sync.** Whenever you change the code or styles it describes, update the matching section here in the same edit. Treat it as the source of truth for "how is this built and why".

## Rendering model

**Math rendering — KaTeX (offline).** KaTeX 0.16.11 is vendored in `vendor/katex/` (`katex.min.css` + `katex.min.js` + `contrib/auto-render.min.js` + woff2 fonts + LICENSE) and loaded synchronously in the `<head>`, so the page needs no internet for math. All math in `exercises.json` is written as `\( ... \)` (inline) / `\[ ... \]` (display, centred; multi-line via `\begin{aligned}` / `\begin{cases}`) — in JSON strings (same escaping as the old JS strings) that means `"\\( ... \\)"` and the aligned row separator is `"\\\\"`. The helper `renderMath(element)` ([app/state.js](app/state.js)) wraps `renderMathInElement` with those delimiters and `throwOnError: false`, guarded so a missing vendor file degrades to raw text instead of breaking the page. It is called in exactly two places: on the whole `exerciseClone` after it is filled (covers question, answers, hints, PF statements, fillIn labels, solution text/more) and on each step's freshly built DOM inside `showStep()` (step captions). Conventions: Polish decimal comma `6{,}38`, tangent `\operatorname{tg}`, CKE intervals `\langle -1, 7\rangle`, emphasised results `\boldsymbol{...}`. Formula *images* for zad 2, 6, 7, 8 and 10's function definition were replaced by KaTeX; the `<img>`s that remain in questions are genuine figures (graphs/drawings). `.katex` is sized `1.08em` in [style/base.css](style/base.css) so formulas blend with the 18px body text.

**Data loading.** Each sheet's data lives in `matura/<id>/exercises.json` (pure JSON — no comments, no functions; this file is the schema's documentation). The file is an **object** `{ "meta": {…}, "exercises": [ … ] }` — `meta` holds the per-sheet chrome (see "Sheet metadata" below), `exercises` is the array of exercise objects. `startSheet()` (bottom of [app/bootstrap.js](app/bootstrap.js)) `fetch`es `matura/${SHEET_ID}/exercises.json`, assigns `dane.exercises` to the global `exercises` array, calls `applySheetMeta(dane.meta)` to fill in the page's title/description/bar-title/PDF paths, and only then calls `loadExercises()`. `startSheet()` distinguishes the failure modes into distinct `.blad-wczytywania` messages instead of rendering nothing: a missing/empty `?arkusz=` (checked before any fetch) or a `fetch` that responds `!ok` (e.g. 404 — no such sheet folder) both show a **"Błędny link"** message with a link back to `index.html` (`pokazBladLinku()`); a `fetch` that throws (no response — `file://` blocks it, or the network is down) shows the "serve the directory with e.g. `npx serve`" hint; a broken JSON body shows a "file may be corrupted" note. `fetch` does not work over `file://`, which is why opening `template.html` directly lands in the second case.

`loadExercises()` (defined in [app/render.js](app/render.js)) runs once on page load. For each entry in the `exercises` array it clones the hidden `#exercise-template` node, fills in the fields, and appends the clone to `#exercises-wrapper`. All per-exercise behavior (answer click handling, hint/solution toggling, step-by-step nav, scoring) is wired up inside this same function at render time — there are no persistent component classes. The answers area dispatches on the exercise **type** (see schema below): `ABCD` single-choice buttons, `PF` true/false rows, `multiSelect` toggle buttons with partial credit, `fillIn` free-text inputs graded by a "Sprawdź" button (each blank worth an equal share of `maxScore`; user input and the `accepted` variants are both run through `normalizeAnswer`, which strips spaces and unifies interval brackets `⟨ ⟩ < >` → `[ ]`, typographic minus → `-`, `;` → `,`), `open` + `selfScore: true` a self-assessment button row (0..maxScore pkt). A per-exercise `setScore(points)` closure centralises scoring: it sets `earnedScore`, updates the badge text + colour tier (`high` = full, `mid` = partial, `low` = 0) and recomputes the total. The hint button hides itself when `hint` is empty (same pattern as the solution button).

**Progress persistence:** answers are saved to `localStorage` under a per-sheet key `matematykazen-postep-<SHEET_ID>` (e.g. `matematykazen-postep-2024-grudzien` — the id is the `?arkusz=` value / folder name, so sheets never share progress) as *what the user clicked/typed* (`{abcd, pf, multi, self, fill}` per exercise). On load, `loadExercises` restores by **replaying those clicks** through the normal handlers, so scoring/colours use the exact same code path — there is no second grading implementation. A save whose exercise count differs from `exercises.length` is discarded (schema changed). The save is wiped (and the page reloaded) by `#reset-scores` in the `#sidebar` panel (labelled "Zresetuj arkusz") — the only such button; a second one under the last exercise (`#clear-progress`) was removed as a duplicate. Multi-part exercises (Zadanie 12, 17) have a separate "parent" entry holding only the shared intro (`maxScore: 0`) — for those the score badge is `remove()`d outright (hiding it wouldn't survive the score-view switcher, which re-sets `display` on all `.exercise-score`).

The widget layer lives in [widgets/](widgets/) (all loaded before the `app/*.js` files): `widgets/_helpers.js` holds the shared helpers (`wgElement`, `wgCanvas`, `wgPointerPos`, `wgDraggable` for pointer-event dragging, `wgPrzyciagnij` soft-snapping of dragged values to a list of target values — used by widgets 1/9/12.1/18 so the "task situation" is easy to hit exactly, `wgStrzalka` arrows; **the `WG_KOLORY` palette, which follows the theme** — a canvas inherits no CSS, so since 2026-08-06 the palette is *read from* the theme's custom properties (`--canvas-bg`, `--wg-*`, `--correct`/`--incorrect`/`--accent-*`; the name→variable map is `WG_ZMIENNE`) by `wgOdswiezKolory()`, which converts `rgb()` to hex because KaTeX's `\textcolor{…}` (zad 18's readout) only takes hex. Widget files must therefore contain **no colour literals at all** — one that slips in simply won't switch themes. Each widget registers its draw function with `wgZarejestrujRysowanie(canvas, draw)`, and `wgPrzemaluj()` refreshes the palette and redraws every still-connected canvas; it is called from `applyTheme()` ([app/theme.js](app/theme.js)) and from a `matchMedia("(prefers-color-scheme: dark)")` listener for the "auto" theme, so switching the theme repaints the widgets instantly, with no page reload; **widget math is KaTeX too**: `wgMath(tex)` is a *memoized* `katex.renderToString` (never the auto-render — live readouts update dozens of times per second while dragging; widget values are quantised so the cache stays small), `wgTexLiczba(v, maxFrac, minFrac)` formats a number for TeX Polish-style (`{,}` decimal comma, `\,` thousand gaps), and `wgUstawHTML(el, html)` swaps a readout's innerHTML only when the string actually changed — titles and the zad 10 formula list render once at build time, readouts go through `wgUstawHTML`; inputs can't live inside a KaTeX formula, so zad 1's `|x + ▢| = ▢` control row is KaTeX fragments glued around the two `<input>`s). Each interactive solution is one global `widget*` function in its own file — `widgets/osLiczbowa.js` → `widgetOsLiczbowa` (zad 1), `widgets/procentSkladany.js` → `widgetProcentSkladany` (5), `widgets/nierownoscKwadratowa.js` → `widgetNierownoscKwadratowa` (9), `widgets/funkcjaPrzedzialami.js` → `widgetFunkcjaPrzedzialami` (10), `widgets/parabola.js` → `widgetParabola` (12.1), `widgets/ciagArytmetyczny.js` → `widgetCiagArytmetyczny` (15), `widgets/koloTrygonometryczne.js` → `widgetKoloTrygonometryczne` (18), `widgets/katWpisany.js` → `widgetKatWpisany` (20), `widgets/prostopadloscian.js` → `widgetProstopadloscian` (30). Widgets build all their DOM inside the container they receive (no fixed ids; every lookup is scoped), so they can coexist on one page. `exercises.json` references them **by name**: `"solutionWidget": "widgetX"` (JSON can't hold functions). The mapping name → function is the `WIDZETY` registry in `widgets/_registry.js`, the last widget-related `<script>` tag in template.html (so every `widget*` function is already a defined global by the time it runs); `loadExercises` (in [app/render.js](app/render.js)) looks the widget up there (unknown names `console.warn` and render nothing). Adding a widget = new file in `widgets/` with a `widget*` function + an entry in `WIDZETY`.

## Exercise data schema (`exercises.json`)

### Sheet metadata (`meta`)

The top-level `meta` object carries everything `template.html` needs to know about *which* sheet it is rendering (so the HTML itself is sheet-agnostic — its `<title>`, `<meta name="description">`, `#sheet-title-heading` and the zasady-oceniania `<object>` start empty/generic and are filled by `applySheetMeta()` at load). Fields:

- `pageTitle` — browser-tab `<title>`.
- `metaDescription` — `<meta name="description">` content.
- `sheetTitle` — text for `#sheet-title-heading` (an `<h1>`, first child of `#exercises-wrapper` so it always sits above the first exercise — `:empty { display: none }` in `style/sheet.css` hides it until `applySheetMeta()` fills it in).
- `zasadyPdf` — path to the CKE marking/answer-key PDF for the zasady-oceniania panel, **relative to the sheet folder** (`matura/<id>/`) — by convention always `"odpowiedzi.pdf"`. It is resolved through `mediaPath()` (like images/videos), so the file lives alongside `exercises.json` in the sheet folder.
- `tablicaPdfDefaultPage` — page number the formula-sheet panel opens on by default (the formula sheet itself, `tablica-wzorow.pdf`, is shared and stays in the repo root — `TABLICE_PDF` in [app/state.js](app/state.js), not per-sheet).

**Styling rule for `exercises.json`:** only put inline HTML/CSS (e.g. a `style="…"` on an `<img>`) into an exercise's data when it is genuinely specific to that one exercise — e.g. Zad 2's inline number image opting out of the block/centred `.question img` rule with `display:inline-block; vertical-align:middle`. Anything that should apply to *all* exercises (answer-button alignment, generic figure sizing, colours, spacing, …) belongs in [style/](style/) — exercise-card rules in `sheet.css`, colours/tokens in `base.css` — never copy-pasted per entry. If you catch yourself adding the same inline style to several exercises, move it to a CSS rule instead.

Each element of `exercises` is an object with this shape (multi-part exercises are separate array entries: a "parent" entry with the shared intro and `maxScore: 0`, then "Zadanie 12.1", "12.2", … as normal entries — the planned `number`/`numberSection` fields are still not implemented):

- `type` — `"ABCD"` | `"PF"` | `"multiSelect"` | `"fillIn"` | `"open"`. Optional: when absent it is inferred (`answers` non-empty → `ABCD`, empty → `open`), so plain multiple-choice entries usually omit it.
- `question` — HTML string, rendered into `.question`. Often embeds `<img>` tags pointing into the exercise's `media/zadN/` folder (sheet-relative; resolved by `mediaPath` — see "Asset folder convention").
- `answers` — array of HTML strings for choice buttons (`ABCD`/`multiSelect`). Empty array (`[]`) for `PF` and `open` exercises.
- `correctAnswerIndex` — (`ABCD`) 0-based index into `answers` of the correct option (`0` = A, `1` = B, …). `-1` or a missing field marks an unfilled exercise: clicking an answer just toggles a single `?` feedback marker instead of grading. `loadExercises` `console.warn`s if the index is out of range.
- `correctAnswerIndices` — (`multiSelect` only) array of correct indices; its length is the number of picks required. Clicks toggle a light-blue `.selected` state; once the required count is selected the picks are graded (green/red) and partial credit is granted (`maxScore · hits / required`, rounded). Deselecting re-opens the choice. When the pick-limit is already reached, clicking a *new* answer replaces the earliest selection (a sliding window — the `selected` `Set`'s insertion order makes the oldest pick its first element) instead of doing nothing, so the student never has to manually un-click to change an answer.
- `statements` — (`PF` only) array of `{ text, answer }` (`answer: true` = P). Each statement renders as a `.pf-row` with its own P/F buttons graded immediately; the exercise scores `maxScore` only when **all** statements are answered correctly, else 0 (CKE-style).
- `blanks` — (`fillIn` only, currently zad 10 and 29) array of `{ label, accepted }`: `label` is the sentence HTML rendered left of the text input, `accepted` the list of recognised answers (compared after `normalizeAnswer` on both sides, so one canonical form like `"(-4,4]"` covers `(−4, 4⟩`, `(-4;4>` etc.; list numeric variants like `"6,38"`/`"6.38"` explicitly). Editing an input clears its previous green/red mark; "Sprawdź" grades all blanks and scores `maxScore · hits / blanks` (rounded).
- `maxScore` — the exercise's point value. `0` marks a "parent" entry (shared intro of a multi-part exercise): no answers UI, no badge (removed from DOM), contributes nothing to the total. All answer paths go through the shared `setScore(points)` helper; `totalScore` is recomputed as the sum of every `earnedScore` (`updateTotalScore()`), so scoring is idempotent and self-correcting — no `isScoreGiven` flag or manual add/subtract.

**Immediate vs. deferred grading (closed exercises).** The "graded immediately / once the required count is selected" behavior above for `ABCD`/`PF`/`multiSelect` is the default (**ON**) of a global toggle — "Poprawność odpowiedzi" (values `natychmiast` / `po „sprawdź"`), in the `#sidebar` panel, stored in `localStorage` key `matematykazen-natychmiastowa-poprawnosc` (global, **no** sheet suffix — like the theme). When **OFF** ("sprawdź później"), clicking an answer only sets a neutral `.selected` state; a floating "sprawdź" button (`.answer-check-floating`, `position: absolute` to the right of `.answers-container`, so it never changes the exercise's height) then reveals the coloring/score and disappears. Each closed branch in `loadExercises` exposes an idempotent `ocen*()` that colors from the stored selection; the per-question button and the "sprawdź wszystkie odpowiedzi" action (in `#sidebar` **and** the sheet footer, both only shown under `body.reczne-sprawdzanie` outside exam mode, `disabled` during an exam — see "Exam mode") call it. `stan.sprawdzone` is persisted so a reload keeps revealed answers colored (with their score) while selected-but-unchecked ones return neutral with the button. **Exam mode always forces immediate** (`natychmiastowaOcenaAktywna()` = the pref **or** `body.tryb-egzaminu`): grading runs as usual under the hood, exam.css hides the colors, and no "sprawdź" buttons appear. `fillIn` keeps its own always-visible "Sprawdź" button regardless of this toggle (it never shows/hides itself).

**`oczekujaceSprawdzenia` registry.** All of the above (`ABCD`/`PF`/`multiSelect`) **and**, since 2026-07-27, `fillIn` and `finalAnswer` push one entry each — `{ ocen, maZaznaczenie, czySprawdzone }` — into the global `oczekujaceSprawdzenia` array (declared in `app/state.js`). `sprawdzWszystkieOdpowiedzi()` (`app/bootstrap.js`, wired to both `#sprawdz-wszystkie` and `#sprawdz-wszystkie-stopka`) iterates it and calls `ocen()` on every entry that `maZaznaczenie()` but not yet `czySprawdzone()` — i.e. exactly what clicking each visible "sprawdź" would do. `fillIn`'s `ocen` is a named `ocenFillIn()` factored out of the "Sprawdź" click handler so both call sites share one grading path (no duplicated `normalizeAnswer`/scoring logic); its `czySprawdzone` reads the DOM (first blank's `correct`/`incorrect` class) rather than a flag, because editing a blank clears that class — the entry must read "unchecked" again without a second piece of state to keep in sync. `finalAnswer`'s entry reuses the existing `ocenKoncowaOdpowiedz()` and is tagged `typ: "finalAnswer"` so `finishExam()` (see "Exam mode") can single it out. A side effect deliberately accepted: "sprawdź wszystkie odpowiedzi" now also **awards points** for `fillIn` (previously only the per-exercise "Sprawdź" did).
- `selfScore` — (`open` only) `true` turns on the off-platform-solve/self-grade flow: a notes `textarea` (placeholder "miejsce na notatki" — **no label**, the four long label sentences were deleted 2026-08-06) plus the `.self-score-container`. Since 2026-08-06 points come from the `gradingCriteria` checklist, not from a `0 pkt`..`maxScore pkt` button row — that row survives **only** as a fallback for `selfScore` exercises whose data carries no criteria (renders under the label "Oceń się:"). Every open exercise in both sheets has criteria, so in practice the buttons are dead code kept for un-migrated data.
- `finalAnswer` — (`open` + `selfScore`, **optional**) `{ label, placeholder, accepted }` — **`label` is no longer rendered** (2026-08-06: the "Twoja ostateczna odpowiedź (…)" caption was one of the four labels removed; the field is left in the data of every sheet and simply ignored by the renderer, so no sheet had to be rewritten): renders a single **"ostateczna odpowiedź"** text input under the notes textarea (`.final-answer-container`) with a "Sprawdź" button (`.final-answer-check`). On check the input is graded exactly like `fillIn` (both the input and every `accepted` variant run through `normalizeAnswer` in [app/answers.js](app/answers.js); note `normalizeAnswer` unifies `⟨⟩<>[]`→`[]` but leaves round parens literal, so a closed interval `⟨-1,7⟩`/`[-1,7]` matches while the open `(-1,7)` does not) and coloured green/red. It **does not touch `earnedScore`** — points still come from the self-score buttons; it is only the single *automatic* correctness signal open exercises get. Also registers itself in `oczekujaceSprawdzenia` (see "`oczekujaceSprawdzenia` registry" above) tagged `typ: "finalAnswer"`, both for "sprawdź wszystkie odpowiedzi" and for the post-exam auto-check described under "Exam mode". **Deliberately lives OUTSIDE `.self-score-container`, so — unlike the checklist and solutions — the INPUT stays available DURING the exam** so there's somewhere to write the result — but the **"Sprawdź" button itself is hidden during the exam** (`body.tryb-egzaminu .final-answer-check` in exam.css), since its colour would reveal correctness mid-exam. The entered value + revealed colour persist under `stan.koncowa`. Absent → no final-answer field.
- `gradingCriteria` — (`open` + `selfScore`) array of `{ tekst, punkty }` (`tekst` = HTML/KaTeX, `punkty` = integer). **This is what scores an open exercise** (changed 2026-08-06 — before that it was an advisory checklist and the student picked the points by hand). It renders as `.ocena-box`, a `<details>` box titled **"Sprawdzanie obliczeń"**, **collapsed by default** so the criteria don't give the solution away on sight; each row is a checkbox + the criterion text + a small points badge (`.kryterium-punkty`, the little brother of `.exercise-score`; a `0 pkt` criterion stays grey even when ticked). Ticking recomputes the score immediately: **sum of ticked `punkty`, clamped to `maxScore`** — the clamp matters because the sum of criteria **does not have to equal `maxScore`** (Zad 9 of `2024-grudzien` has three criteria worth 0+1+1 for a `maxScore: 2`, the first step earning nothing on its own).
  **Where the numbers come from:** the criteria mirror the *thresholds* of the official CKE marking key (`matura/<id>/odpowiedzi.pdf`) one-to-one — one criterion per point level, its alternatives ("ALBO" branches of the key) joined into one sentence with "lub", each worth 1 pkt (decision by Henrich, 2026-08-06). The key is a cascade ("1 pkt — …, 2 pkt — the above and …"), not a list of independent steps, so the student ticks every threshold reached. All 15 open exercises of both sheets are written this way. A string entry (the pre-2026-08-06 shape) still renders, as a 0-point criterion plus a `console.warn`.
  Checkbox state persists under `stan.kryteria`; the **score is not persisted** — it is recomputed from the ticks on load (`przeliczKryteriaZadania()` in the restore block), so there is one scoring path, as everywhere else. Opening the box sets `stan.ocenaOtwarta`, which is what "this exercise has been graded" means for the post-exam indicators (see "Oceń się" phase): a student who reviewed the list and ticked *nothing* has still graded the exercise — at 0 pkt. Being inside `.self-score-container`, the whole box is hidden during an exam. The general legal disclaimer in the sheet footer (`.samoocena-disclaimer`) covers this — the site is not an examiner.
- `hint` — HTML shown/hidden by the "Podpowiedź" button; empty string hides the button entirely.
- `formulasPage` — page number into `tablica-wzorow.pdf`, or `null` to hide the "Pokaż wzory" button. The PDF's printed page numbers match the physical ones 1:1 (verified 2026-07-28 — footers read "Strona N z 34" on physical pages 4–34; pages 1–3 and 35–36 carry no footer), so no offset is needed. Clicking it calls `openFormulasAtPage(page)`, which replaces the PDF `<object>` inside `#tablica-wzorow-panel` entirely (changing just `data` doesn't reliably reload PDF viewers) and then shows the panel via `showFormulasPanel()`. Targeting a *specific formula* on the page via the `&view=FitH,<top>` open parameter was built and tested on 2026-07-28, then **rejected**: Firefox and Brave scrolled correctly, but Chrome and Edge landed far too low, with the formula off-screen entirely. Page granularity is all this mechanism gets — don't retry it. Show/hide is centralised in `showFormulasPanel()`/`hideFormulasPanel()` (they toggle the panel's `display` and keep the `#toggle-tablica` label in sync); the sidebar item and the in-panel close button (`#tablica-close`, the ✕ in its top-right corner) both go through them. A mirrored second panel `#zasady-oceniania-panel` (left-hand side) shows the official CKE answer/marking PDF whose path comes from `meta.zasadyPdf` (set on the `<object id="zasady-oceniania">` by `applySheetMeta`, resolved through `mediaPath` + `encodeURI`); it has its own `#toggle-zasady` sidebar item and `showGradingRules()`/`hideGradingRules()`/`#zasady-close`, but no per-page targeting. Both panels are "unlocked": `makePanelDraggable(panel)` makes the top strip (`.panel-uchwyt`) drag the panel (switching it to `left/top` positioning) and the bottom-right grip (`.panel-rozmiar`) resize it, using pointer capture on the handles because the PDF `<object>` swallows mouse events. The **only** drag constraint is on `top`: it is clamped to `0`, i.e. the top edge of the page (decision 2026-07-27) — the panel *may* be dragged up level with the logo and will slide **under** it (`#logo` sits at z-index 10, the panels at 9, and the logo's fixed 200px background rectangle keeps it readable); the clamp exists only so the drag strip can never disappear above the viewport; `left` (and hence right/bottom) is deliberately **unclamped** — the panel may be dragged partly or fully off any other screen edge. Resize is unconstrained.
- `solutionText` / `solutionTextMore` — HTML for the solution panel; `solutionTextMore` is behind an extra "Pokaż więcej" toggle and its container auto-hides when empty.
- `solutionStepByStep` — either `null` or an array of `{ type: "video"|"image"|"text", src, text }` steps, rebuilt 2026-08-11 around one idea: **a dot is a STATE of the expression, a film is the TRANSITION between two states**, so an exercise with N films gets N+1 dots. Everything else follows from that. The playhead sits on the dot you are actually at — the segment's left dot while its film is still running, the right dot once it has finished — and the same in reverse, the other way round. Files live in `matura/<sheet>/media/zadN/solution-step-by-step/` as `stepM.mp4` next to `stepMreverse.mp4`; the player derives the reverse name from `src` by inserting `reverse` before the extension, so data lists only the forward file.

  The UI under the film is three rows (`template.html`): **ROW 1** dots + progress, **ROW 2** ◄ / play-pause / ► with 44×44 touch targets, **ROW 3** a collapsed `<details>` holding the step's `text`. The progress bar that used to be a strip under the film now fills the *segment between the current dot and the next one* (`--postep` on `.step-link`, written by `rysujPostep`); its `requestAnimationFrame` loop runs only while a film plays and self-terminates on pause/end or when the `<video>` leaves the DOM (`!isConnected`) — no CSS transition, an earlier `timeupdate`+transition combo made the bar move rubber-band-like. Above seven dots the strip scrolls horizontally and `zbudujKropki()` reveals the side arrows. Dots are clickable and land on a step's **first** frame, paused; the last dot is the end state, shown as the final film's last frame.

  **Step switching is double-buffered against flicker:** `przygotujKrok()` builds the next step's DOM detached, and the old step stays visible (frozen on its last frame) until the new film has its first frame decoded *and seeked into place* (1.5 s `setTimeout` fallback) — only then `replaceChildren` swaps and `video.play()` starts. Waiting for `seeked`, not just `loadeddata`, matters for reverses: frame 0 of a reverse is the step's END state, which is exactly the frame that must not flash. A per-exercise `swapToken` guards against rapid clicking. **The target time is re-applied after insertion** (`ustawCzasWideo`) because a detached element is loaded lazily and often misses the fallback — without that, clicking the last dot showed the first frame of the last step instead of the end state (caught 2026-08-11 by reading canvas pixels, not by looking at a screenshot).

  `podepnijSterowanieWideo(ctx, video)` runs on the attached element (JS properties can't be set on the string `renderStep` returns): playback speed from the global `predkoscWideo()` setting (0,25×–4×, sidebar), click-to-toggle play/pause, the `.paused`/`.ended` classes driving `.video-overlay-icon`, and the aspect ratio — `--proporcje-filmu` is read from `videoWidth/videoHeight`, so 16:9 (zad. 2) and legacy 21:9 films (zad. 1 and 3) each get a box that fits them instead of ~80 px of dead band. Keyboard ← → drive the player last interacted with (`aktywnyOdtwarzaczKrokow`), and `podepnijPrzesuwanie` maps swipes onto the same two actions. Reaching the last step **no longer** calls `markCorrectAnswer()` — Henrich found revealing the answer that way misleading (removed 2026-08-11). The invisible `.step-counter` is still filled, because `krokRozwiazania()` in `app/report.js` reads it for bug reports. The "Rozwiązanie" button itself is hidden in `loadExercises` when an exercise has no solution content at all (no text/steps/interactive/more).
- `solutionWidget` — either `null` or the **name** (string) of one of the `widget*` functions described under "Rendering model", e.g. `"widgetOsLiczbowa"`; `loadExercises` resolves it through the `WIDZETY` registry in `widgets/_registry.js` and calls the function with the exercise's `.solution-interactive-container`. Nine exercises currently have widgets (1, 5, 9, 10, 12.1, 15, 18, 20, 30).

## Asset folder convention

Every sheet keeps its assets under **`matura/<id>/media/zadN/`** (one `zadN/` folder per exercise number, not array index), e.g. `matura/2024-grudzien/media/zad1/zad1rozw_step1.mp4` (rozwiązanie = solution), `matura/2024-grudzien/media/zad10/zad10rys.png` (a real figure). In `exercises.json` these are written **relative to the sheet folder** with the `media/` prefix — `"media/zad1/zad1rozw_step1.mp4"`, `<img src="media/zad10/zad10rys.png">` — the same convention for both sheets.

**Path resolution — `mediaPath(src)`.** Because `template.html` renders from the repo root (not from inside the sheet folder), a bare `media/…` path would resolve against the root. `mediaPath(src)` (top of [app/state.js](app/state.js)) prepends `matura/${SHEET_ID}/` to any non-absolute path (leaves `http(s):`/`data:`/`/…` untouched). It is applied in three places: the `<img>`/`<video>`/`<source>` `src` inside step HTML (`renderStep`), the next-step preload, and — via a `querySelectorAll("img[src]")` sweep of the freshly built exercise clone (just before `renderMath`) — every `<img>` embedded in the question/hint/solution HTML. The `meta.zasadyPdf` path goes through `mediaPath` too. So **paths in `exercises.json` stay sheet-relative; `mediaPath` is the single place that joins them to the sheet folder** — don't hard-code `matura/<id>/` into the data.

Keep filenames **lowercase** — `zad17.PNG` once broke on case-sensitive hosting and had to be renamed. Since the KaTeX migration (2026-07-06) the formula crops `zad2/zad2.png`, `zad6/zad6*.png`, `zad7/zad7*.png`, `zad8/zad8.png`, `zad10/zad10.png` and the whole `zad16/` folder were no longer referenced (their content is typeset in KaTeX) and were deleted. The 2026-maj figures (`media/zad12/…` etc.) are still to be cut from that sheet's exam PDF, so those paths currently 404 — expected until the images are added.

Each sheet's own source PDFs live in its folder too, under four fixed names — `arkusz.pdf` / `arkusz.txt` (the exam) and `odpowiedzi.pdf` / `odpowiedzi.txt` (the CKE marking key, the one `meta.zasadyPdf` points at). The names are identical in every sheet folder **on purpose**: the path can be built from `<id>` alone, without listing the directory. The shared formula sheet `tablica-wzorow.pdf` stays in the repo root; its per-section Markdown transcript is in `tablica-wzorow-transkrypt/`.

**[matura/README.md](matura/README.md) is the source of truth for what lives in a sheet folder** and which sheets exist (session, próbna vs właściwa, CKE sheet symbol, wired or not) — update it there when a sheet is added, and don't restate the list here or in CLAUDE.md.

Step-by-step solution videos are produced externally with **Manim** (the Python math-animation library), then exported as short `.mp4` files into `media/zadN/solution-step-by-step/` — they aren't generated or editable from within this repo, only referenced and played back (see `solutionStepByStep` above). The **reverses are not rendered by Manim**: `tools/rewersy.sh` derives each `stepMreverse.mp4` from the finished `stepM.mp4` with `ffmpeg -vf reverse`, so the two can never drift apart, plus a `tpad` hold on the end (reversing moves the scene's closing hold to the *start* of the reverse, and the browser would otherwise stop a few frames short of the step's opening frame — see `issues/krok-po-kroku-produkcja.md`).

## Scoring / UI chrome

`maxTotalScore` is computed inside `loadExercises()` as the sum of all `maxScore` fields (the old hand-maintained constant at the top of the data file is gone — nothing to keep in sync). Answer progress itself *is* persisted — see "Progress persistence" under Rendering model.

## Exam mode (tryb egzaminacyjny)

"Rozpocznij próbny egzamin" runs a timed mock exam. Logic is all in [app/exam.js](app/exam.js), styling in [style/exam.css](style/exam.css), the "oceń się" follow-up phase in [app/indicators.js](app/indicators.js); the shared constants/keys (`KLUCZ_EGZAMINU`, `CZAS_EGZAMINU_MS`) sit in [app/state.js](app/state.js)/exam.js. The section below is organised by sub-topic.

**Design principle — one grading path.** Grading and progress-saving keep running through the *exact same* code path as normal mode; the mode only adds a `body.tryb-egzaminu` class, and [style/exam.css](style/exam.css) under that class hides everything that would reveal the result. Specifically: `.correct`/`.incorrect` on answer buttons, `.pf-row` buttons and `.fill-in-input` are restyled to the neutral blue "selected" look (`--accent-blue`), and `display: none !important` hits the whole `.light-button-container` (the Podpowiedź / Rozwiązanie / Zgłoś błąd / Pokaż wzory row), `.self-score-container` (self-score buttons **and** the `gradingCriteria` checklist), `.exercise-score` badges, `#total-score`, `#toggle-zasady` (the CKE answer-key PDF) and `.answer-check-floating` (the `!important` is needed because several of those get an inline `display` from JS). The final-answer "Sprawdź" button (`.final-answer-check`) is likewise hidden (plain `display: none`, not `!important` — it never gets an inline style). `#sprawdz-wszystkie`/`#sprawdz-wszystkie-stopka` are **not** hidden any more — like the other `OPCJE_MENU_EGZAMIN` items they stay visible but `disabled`/greyed (see "Start / end controls" below), so the control doesn't appear to vanish. What deliberately **stays usable** mirrors the real matura: the CKE **formula sheet** (`#toggle-tablica` + each exercise's "Pokaż wzory") — see "Formula sheet allowed" below — the per-exercise **tok-rozwiązania textarea** (`.open-answer-container`, a place to write the solution), and the open-exercise **"ostateczna odpowiedź" input** (`.final-answer-container`, schema `finalAnswer`) — the field itself stays live so there's somewhere to write the result, but its "Sprawdź" button is hidden as noted above, so it no longer grades mid-exam.

**State & persistence.** Exam state is `{ start: timestamp }` under its own per-sheet localStorage key `matematykazen-egzamin-<SHEET_ID>` (`KLUCZ_EGZAMINU`, e.g. `…-2024-grudzien`), fully independent of the answer-progress key (`KLUCZ_POSTEPU`). Because it survives a refresh, a reload *resumes* the exam: `if (readExamState()) enableExamMode()` runs at script load, before any rendering, so there is no flash of scores. Duration is `CZAS_EGZAMINU_MS` = **170 min** (matura podstawowa). **Hidden test switch:** the URL param `?test-egzamin=1` (not surfaced anywhere in the UI) shortens it to **1 minute** for quickly exercising the whole flow incl. the auto-end; the start-confirm text shows the real minutes (`CZAS_EGZAMINU_MIN`) rather than a hard-coded "170".

**Start / end controls (paired buttons, one handler each).** Start and end each have two buttons in different places, both wired to one shared function so their behaviour can't drift: `#egzamin-start` (in `#sidebar`) + `#egzamin-start-stopka` (sheet footer) → `startExamPrompt()`; `#egzamin-koniec` (a static button placed *after* `#exercises-wrapper`, hidden outside exam mode) + `#egzamin-koniec-bar` (the pill in `#naroznik-prawy`) → `finishExamPrompt()`. Both halves of `#tryb-przelacznik` call the same two prompts, so the switch under the sheet title is a third entry point with no duplicated logic. Starting `confirm()`s, then **writes `KLUCZ_EGZAMINU` first** and only then wipes `KLUCZ_POSTEPU` + the `KLUCZ_OCENIANIA` self-assessment-phase flag (so a failed `setItem` on full/blocked storage doesn't nuke progress for an exam that never started), and reloads — a fresh render gives a clean sheet in exam mode from the first frame. While the exam runs, `odswiezBlokadyMenu()` leaves the menu-only options (`OPCJE_MENU_EGZAMIN`: `#show-all-solutions`, `#score-switch-button`, `#reset-scores`, `#egzamin-start`, `#sprawdz-wszystkie`, `#sprawdz-wszystkie-stopka`, and since 2026-08-09 `#natychmiastowa-toggle` — correctness is hidden during the exam anyway, so "when to reveal it" changes nothing) **visible but `disabled`** (greyed via `#sidebar button:disabled` in sheet.css) rather than hidden, so `#sidebar`/the sheet footer aren't left looking like the control disappeared; `finishExam()` calls the same function again to re-enable them. `odswiezBlokadyMenu()` (renamed from `setExamMenuDisabled()` on 2026-08-09) is the **single writer** of `disabled` on those buttons, because there are now two independent reasons to block one: the running exam, and — for `#sprawdz-wszystkie`/`#sprawdz-wszystkie-stopka` (`OPCJE_TYLKO_RECZNE_SPRAWDZANIE`) — immediate-correctness mode, in which the action has nothing to reveal. With two separate setters, ending the exam would re-enable "sprawdź wszystkie" regardless of the correctness mode. It is therefore also called from `odswiezTrybPoprawnosci()` in `app/bootstrap.js`, and it stashes each button's original `title` in `dataset.titleBazowy` so unblocking restores it instead of clearing it.

**Timer.** `tickExam()` runs every second (`egzaminInterval`), writing `#egzamin-timer` (tabular-nums; `.malo-czasu` turns it red under 10 min) and auto-ending at 0. The auto-end is **guarded on `exercises.length`** so a timer that expired while the tab was closed ends the exam right after the data loads — `startSheet()` fires one `tickExam()` after `loadExercises()` for exactly this case. The `#zegar-toggle` menu option (global key `matematykazen-zegar-widoczny`) only toggles the `.zegar-ukryty` class on the span (visibility); the clock keeps ticking and still auto-ends in the background.

**Finishing & summary.** Ending (either button, or timeout) removes `KLUCZ_EGZAMINU` + the class, clears the interval, closes the formula panel if open (`hideFormulasPanel()`), **auto-checks every pending `finalAnswer` field** (loops `oczekujaceSprawdzenia`, calling `ocen()` on entries with `typ === "finalAnswer"` that have a value but aren't graded yet — see "`oczekujaceSprawdzenia` registry" above; filtered by `typ` specifically so this does **not** also reveal closed exercises the student never asked "sprawdź wszystkie odpowiedzi" for), and fills the `#egzamin-podsumowanie` overlay: closed-exercise score (`earnedScore` sum vs non-`selfScore` `maxScore` sum), percentage, time used, and an explicit note that **open (`selfScore`) exercises are scored by self-assessment only now, after the exam** — their self-score rows and the solutions just unlocked, and self-graded points flow into the same running total. Answers given during the exam keep their now-revealed colours (same DOM, class removed).

**"Oceń się" phase (post-exam).** `finishExam()` also flips on `ustawFazeOceniania(true)` ([app/indicators.js](app/indicators.js)): a `KLUCZ_OCENIANIA` localStorage flag (own per-sheet key, survives refresh) that, while set, shows a floating yellow dot (`.wskaznik-otwarte`) next to every open exercise that still needs self-grading — click scrolls to it, grading it (or the phase's own "Ukryj wskaźniki" control) clears its dot, and the phase auto-turns off once every open exercise is graded. On a plain page load `startSheet()` calls `pokazWskaznikiOtwarte()` when the flag is set (and no exam is running) so the dots survive a refresh. Which exercises get a dot is the `#wskazniki-tryb-toggle` setting ("Wskaźniki" in the `#sidebar` panel, global key `matematykazen-tryb-wskaznikow`), **three** states since 2026-07-27: `wszystkie` (default — every ungraded open exercise, because the working-notes box is optional), `wypelnione` (only those with text typed in), and the new `wyl` (no dots at all). `wyl` returns early from `pokazWskaznikiOtwarte()` *without* calling `ustawFazeOceniania(false)` — otherwise switching back to `wszystkie` would have nothing left to restore. localStorage keeps those ASCII ids; the panel shows the `wył.`/`wypełnione`/`wszystkie` labels from `data-stany`.

**Mode switch.** `#tryb-przelacznik` (a segmented control under the sheet title, second child of `#exercises-wrapper`) *always* shows the current mode and is also how you enter and leave it. `updateModeSwitch()` — the renamed successor of `updateModeSubtitle()`, called from `enableExamMode()` and `finishExam()` — is the **only** writer of its `.aktywny` class and `aria-pressed`, reading `body.tryb-egzaminu` as the source of truth. The click handlers deliberately change nothing visually; they just call `startExamPrompt()` / `finishExamPrompt()`, so a cancelled `confirm()` leaves the switch exactly as it was. Clicking the already-active half is a no-op. It is normal chrome, not exam-only, and is hidden only until `body.arkusz-wczytany` (so it never appears on a bad-`?arkusz=` error page). The half labelled "ćwiczenia" is deliberately **not** in `OPCJE_MENU_EGZAMIN` — it is the one way out of an exam besides `#egzamin-koniec`.

**Multi-tab sync.** Two tabs of the same sheet do **not** stay live-synced during an exam — `finishExam()`/`KLUCZ_EGZAMINU` removal fires only in the tab that ended/timed out. Other tabs learn about it via a `storage` event listener (which fires only in *other* tabs) keyed on `KLUCZ_EGZAMINU` being removed: they stop their timer and show a "finished in another tab" overlay prompting a reload, rather than rendering a second, possibly-inconsistent summary from their own in-memory scores. (See issues/dwie-karty-tryb-egzaminu.md for the original bug.)

## Zgłaszanie błędów w zadaniu (report an error)

Lives in [app/report.js](app/report.js) (loaded just before `render.js`, because `loadExercises` calls into it per exercise). For every rendered exercise `dodajLinkZgloszenia(exerciseClone)` inserts a `.report-error-link.light-button` ("Zgłoś błąd") **into `.light-button-container`, before `.formulas-button`** — i.e. the row reads Podpowiedź / Rozwiązanie / Zgłoś błąd / Pokaż wzory (changed 2026-08-06; it used to be a smaller, fainter standalone line under the whole card, and it now inherits the light-button look, hides with that row during an exam, and shares its flex sizing) — the exercise number is parsed from the question text (`/Zadanie\s*([\d.]+)/i`, matching `numerZadania()` in render.js so sub-numbers like "12.1" survive; a trailing full stop is trimmed), because array index ≠ CKE numbering.

**Inline, not a modal (changed 2026-07-26).** There is exactly **one** `#zglos-blad-overlay` in template.html, and `otworzModalZgloszenia(numer, karta)` **moves that single node** into the clicked exercise card with `karta.insertBefore(zgOverlay, karta.querySelector(".light-button-container"))` — `insertBefore` *moves* a node rather than copying it, so IDs stay unique and every `getElementById` in report.js keeps working. It lands directly under the answer buttons and **above** the `[Podpowiedź][Rozwiązanie]` row, so the student can still see the exercise text while describing the bug (the reason for the change; matters most on phones). Consequences: no backdrop, so there is no click-outside-to-close — closing is `Anuluj` / `✕` / Escape (`czyFormularzOtwarty()` guards the Escape handler). Clicking the link of the **same** exercise again collapses the form (toggle, like "Podpowiedź"); clicking another exercise's link moves it there and **resets** the fields, so a description started on zad. 7 can't be submitted against zad. 9. `zgAktualnaKarta` tracks which card currently hosts the form.

**Toggle:** `#zglos-blad-toggle` ("Zgłoś błąd pod zadaniem", values `wł.` / `wył.`) in the `#sidebar` panel enables/disables the link **globally** (localStorage key `matematykazen-zglaszanie-bledow`, no sheet suffix — like the theme; only `"0"` disables, default on), by toggling `body.bez-zglaszania` which the CSS uses to hide all `.report-error-link`. Same pattern as the other sidebar settings (`#natychmiastowa-toggle`, `#wskazniki-tryb-toggle`).

**Submission** goes to **Formspree** via a hand-rolled `fetch` (AJAX, no page reload) — this is Formspree's documented AJAX approach, deliberately **not** the `@formspree/ajax` SDK: that ships from `unpkg.com`, which would break the offline-first rule this project follows by vendoring KaTeX locally, and there is no bundler or npm here. `FORMSPREE_ENDPOINT` is live (`https://formspree.io/f/xvzedgjg`); a regex on it still guards the submit, so if it is ever replaced by a placeholder the user gets a clear "Zgłoszenia nie są jeszcze skonfigurowane" toast instead of a confusing network error.

**Fields.** The description textarea is **obligatory and length-bounded** (changed 2026-07-26) — `OPIS_MIN = 3` / `OPIS_MAX = 2000`, both measured **after `trim()`** so spaces neither satisfy the minimum nor eat the maximum. `bladOpisu()` is the single source of truth: it returns the message for empty / too-short / too-long, or `""` when valid, and both the button state and the error text derive from it. Three signals at once: `.zglos-blad-wyslij` starts `disabled` and `odswiezPrzyciskWyslij()` enables it only when `bladOpisu()` is empty; the submit handler re-checks and calls `pokazBladOpisu()`, which fills `#zglos-blad-blad` (`role="alert"`), adds `.zglos-blad-pole-blad` (red border) and re-focuses the field — needed because `requestSubmit()`/Enter can bypass `disabled`. Typing **updates** a visible message live rather than only clearing it (one character must turn "bez tego nie wiemy, czego szukać" into "opis jest za krótki"). The upper bound is enforced twice: `maxlength="2000"` on the textarea (the browser refuses to type or paste past it) **and** in `bladOpisu()`, since `maxlength` is trivially bypassed programmatically — **keep the HTML attribute and the JS constant in sync**. `#zglos-blad-licznik` shows a live `n / 2000` counter that turns red (`.zglos-blad-licznik-blisko`) past 90%; it is `aria-hidden` because screen readers get the limit through the `role="alert"` message instead. `odswiezLicznikOpisu()` must be called wherever the field is reset (form open, successful send), not just on input. The label deliberately carries **no** "(obowiązkowy)" suffix. Rationale for the cap: an unbounded description produced a multi-kB submission in testing, which bloats both the inbox and the Formspree payload. Email stays optional. `#zglos-blad-kategorie` holds eight **multi-select pills** — plain `<button type="button" data-kategoria="…">` toggling `.selected`, reusing the look of the ABCD answer buttons; multi-select is *cheaper* than single-select (no sibling deselection). Categories are optional and land in the payload as a comma-joined `kategorie` string (or `"bez kategorii"`), which is also interpolated into `_subject` so the inbox can be triaged from the subject line alone.

**Auto-attached (user types none of it):** exercise number, `SHEET_ID`, `location.href`, effective theme (`aktualnyMotyw()` distinguishes manual jasny/ciemny from auto and resolves what auto currently means), exam-vs-practice mode, `navigator.userAgent`, the whole of `localStorage`, plus (added 2026-07-26, all read straight from the host card's DOM so neither `render.js` nor `steps.js` had to change): `odpowiedzUcznia()` (selected/graded `.answers-container` buttons, `.fill-in-input` values with their labels, `.final-answer-input`) — all of these go through **`tekstOdpowiedzi(el)`**, which is required whenever reading text out of an element that may contain KaTeX: KaTeX renders every formula **twice** (a hidden `.katex-mathml` layer for screen readers, including the raw LaTeX in `<annotation>`, plus the visible `.katex-html`), so a bare `.textContent` concatenates both and yields garbage — `"A. 545^{4}54"` for zad. 2's answer "A. 5⁴" (bug found in production 2026-07-26, fixed same day). `tekstOdpowiedzi` clones the node (never mutating the live DOM), swaps each `.katex` for its `annotation[encoding="application/x-tex"]` text and returns `"A. 5^{4}"` — the raw LaTeX is used deliberately because the visual layer flattens 5⁴ to an ambiguous `"54"`, `odpowiedzPoprawna()` (the `.hiddenCorrect` button — see `markCorrectAnswer` in answers.js), `krokRozwiazania()` (the `.step-counter` text, e.g. `"3 / 7"`, since `steps.js`'s `ctx` is per-exercise and unreachable from here) and `daneEkranu()` (viewport, screen, DPR, orientation). A `<details>` in the form previews all of it for transparency.

**Anti-spam:** a honeypot field `input[name="_gotcha"]` (Formspree's native honeypot name), hidden from humans by CSS (`.zglos-blad-hp` positioned off-screen, **not** `display:none`, so bots still fill it) — if filled, the submit fakes a success toast and sends nothing. Plus light **throttling**: no send more than once per minute (`matematykazen-zglos-ostatnia` timestamp, global) to protect the Formspree free tier's 50-submissions/month cap. The throttle timestamp is set only when the request actually **reaches** the server (any HTTP response), not on a pure network failure (so a user can retry immediately after losing connection) and not for the placeholder short-circuit.

**Feedback:** a toast (`.zglos-toast`, created lazily, bottom-centre, green `--correct` border for success / red `--incorrect` for errors) — "Dziękujemy, zgłoszenie wysłane." on `res.ok`; distinct error messages for a non-ok response (e.g. 429 = monthly limit), a network exception, throttle, and the unconfigured placeholder — never a silent failure.
